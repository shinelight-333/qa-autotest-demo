# Примеры баг-репортов

Три карточки оформлены по сохранённым результатам API-тестов от **07.10.2026**.
Это исторические наблюдения на локальном учебном демо-сайте с намеренными дефектами.
При подготовке репозитория сценарии заново не выполнялись.

Источник результатов — [обезличенная выдержка](evidence/api-runs.json) из исходных
pytest-html отчётов. Сводка и ограничения — в [результатах](results.md).
Версия приложения, точные флаги дефектов и часовой пояс старых запусков не сохранены в этой выдержке.
Severity и priority ниже — оценка влияния по требованиям, а не согласованные производственные статусы.

## BUG-API-01 — Покупатель может прочитать чужой заказ по ID

| Поле | Значение |
|---|---|
| Область | API, разграничение доступа |
| Severity / Priority | Critical / High |
| Окружение | Локальный демо-магазин; исторический запуск Python 3.12 / pytest |
| Источник | `api.html`, 07.10.2026, 19:35:58 — время как в отчёте |
| Автотест | `test_api_01_foreign_order_is_not_readable` в [API-наборе](../tests/api/test_api_defects.py) |
| Статус | Исторически обнаружен; в `fixed-api.html` этот тест имеет Passed; текущий прогон не выполнялся |

**Предусловия:** два новых покупателя A и B с разными сессиями; A создал собственный заказ.

**Шаги:**

1. Сохранить ID заказа A.
2. Авторизоваться как B в отдельной HTTP-сессии.
3. Выполнить `GET /api/v1/orders/{ID_ЗАКАЗА_A}/`.

**Ожидается:** HTTP `404`; данные чужого заказа недоступны.

**Фактически:** HTTP `200`. В диагностике исходного отчёта зафиксировано:
`GET /api/v1/orders/10/: ожидался HTTP 404, получен 200`.
Число `10` относится только к старому запуску; для повторения нужен новый заказ.
Состав ответа этой выдержкой не подтверждается: тест остановился на проверке HTTP-кода.

**Влияние:** нарушается изоляция личных ресурсов покупателей.
**Повторная проверка:** результат Passed присутствует в более позднем отчёте,
но без привязки к версии приложения его нельзя считать подтверждением состояния текущего стенда.

## BUG-API-07 — Пробелы по краям поискового запроса меняют выдачу

| Поле | Значение |
|---|---|
| Область | API, каталог и поиск |
| Severity / Priority | Medium / Medium |
| Окружение | Локальный демо-магазин с учебным каталогом |
| Источник | `api.html`, 07.10.2026, 19:35:58 — время как в отчёте |
| Автотест | `test_api_07_search_trims_surrounding_spaces` в [API-наборе](../tests/api/test_api_defects.py) |
| Статус | Исторически обнаружен; в `fixed-api.html` этот тест имеет Passed; текущий прогон не выполнялся |

**Предусловия:** в каталоге есть товары, найденные по слову «палатка».

**Шаги:**

1. Получить `/api/v1/products/` с параметрами `search=палатка` и `page_size=50`.
2. Повторить запрос с `search= палатка `, сохранив пробелы по краям.
3. Сравнить `count` и ID найденных товаров.

**Ожидается:** результаты одинаковы; поиск игнорирует крайние пробелы.

**Фактически:** обычный запрос вернул 6 товаров, запрос с пробелами — 0.
В исходном отчёте: `assert 0 == 6`.
Сравнение ID не было достигнуто после падения проверки количества.

**Влияние:** покупатель не находит существующий товар при случайном пробеле в запросе.

## BUG-API-14 — Отмена не возвращает зарезервированную последнюю единицу

| Поле | Значение |
|---|---|
| Область | API, заказы и складской остаток |
| Severity / Priority | High / High |
| Окружение | Локальный демо-магазин, `CAMP-LAST` |
| Источник | `api.html`, 07.10.2026, 19:35:58 — время как в отчёте |
| Автотест | `test_api_14_cancellation_restores_last_unit` в [API-наборе](../tests/api/test_api_defects.py) |
| Статус | Исторически обнаружен; последующий прогон заблокирован неверными исходными данными |

**Предусловия:** новый покупатель; исходный остаток `CAMP-LAST` равен **1**.

**Шаги:**

1. Добавить одну единицу `CAMP-LAST` в корзину.
2. Создать заказ; проверить, что остаток стал 0.
3. Отменить заказ; проверить статус `cancelled`.
4. Получить товар и проверить остаток.

**Ожидается:** после отмены остаток снова равен 1.

**Фактически:** остаток остался 0; исходный отчёт содержит
`assert 0 == 1` на проверке остатка после отмены.

**Влияние:** товар остаётся недоступным после отмены неоплаченной покупки.

**Ограничение повторной проверки:** в `fixed-api.html` этот сценарий упал уже
на исходном условии `stock == 1`, потому что остаток был 0. Это другой этап падения:
он не доказывает ни сохранение, ни исправление исходного дефекта. Перед повторением
нужно отдельно восстановить учебные данные.
