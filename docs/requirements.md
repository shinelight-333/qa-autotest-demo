# Поход: требования к сервису

Магазин туристического снаряжения с каталогом, избранным, корзиной и личным кабинетом. Это описание ожидаемого поведения; фактическое поведение нужно проверить самостоятельно. Все покупки учебные, деньги не списываются. Пустые блоки вместо изображений согласованы и не являются дефектом.

## Пользователи

Гость может просматривать каталог, товары и отзывы. Для личных ресурсов нужен вход. Пользователь работает только со своими адресами, избранным, корзиной и заказами. Чужой ресурс по ID возвращает `404`.

Регистрация: email уникален без учёта регистра, крайние пробелы удаляются. Имя — 2–80 символов после удаления крайних пробелов; пароль от 8 символов, слишком распространённые значения запрещены. В интерфейсе повтор пароля должен совпадать с первым полем. Email профиля изменить нельзя. Телефон необязателен; заполненный телефон состоит из `+` и 10–15 цифр, первая цифра не ноль.

После выхода серверная сессия завершается. Следующий пользователь не должен видеть личные данные предыдущего. После успешного сохранения данные доступны при перезагрузке и повторном входе.

## Адреса

Адрес состоит из получателя, телефона, города, улицы, дома, необязательной квартиры и шестизначного индекса. Получатель — 2–80 символов; телефон в указанном выше формате. Можно создавать, изменять и удалять собственные адреса. Не больше одного адреса по умолчанию; первый созданный адрес становится основным.

Изменение адреса в профиле не изменяет условия уже оформленного заказа.

## Каталог

Показываются только активные товары. Поиск по названию игнорирует регистр и пробелы по краям. Фильтры: категория, минимальная/максимальная цена, наличие. Границы цены включительные, неотрицательные; минимум больше максимума — ошибка `400`.

Сортировки: название, цена по возрастанию/убыванию, новинки. Если значения равны, дополнительная сортировка по ID. По умолчанию 12 товаров на страницу; API допускает `page_size` от 1 до 50. За концом списка возвращается пустой `results`. Соседние страницы одной неизменной выборки не должны повторять позиции.

Изменение фильтра возвращает на первую страницу, полный сброс удаляет все ограничения. Возврат из карточки кнопкой браузера восстанавливает фильтры, сортировку и страницу. Нулевой остаток отображается как «Нет в наличии», товар нельзя купить. Неактивный товар недоступен для новой покупки.

## Избранное и корзина

Избранное сохраняется между входами. Повторное добавление в избранное не создаёт дубль. В корзине один товар представлен одной строкой. Повторное добавление увеличивает её количество.

Количество — целое от 1 до 99, не больше доступного остатка. Нулевое количество не заменяет удаление строки. Все изменения количества пересчитывают суммы. В корзине используется текущая цена, в оформленном заказе — зафиксированная при покупке.

## Оформление, доставка и скидки

Валюта — рубли, точность — копейки. Округление скидки выполняется до двух знаков: половина копейки округляется вверх. Клиент не назначает цены или суммы заказа.

```text
Стоимость товаров = сумма(цена × количество)
Скидка = стоимость товаров × процент промокода, округлённая до копеек
Итого = стоимость товаров − скидка + доставка
```

Самовывоз бесплатен и не требует адреса. Курьер стоит 300 ₽, но бесплатен при стоимости товаров после скидки от 5 000 ₽ включительно. Для курьера необходим выбранный собственный адрес, который сохраняется в заказе снимком.

Один промокод на заказ. `HIKE10` — скидка 10% при стоимости товаров до скидки от 2 000 ₽, один раз на пользователя. Пробелы по краям и регистр кода игнорируются. Код должен быть активен, его дата начала уже наступила, дата окончания ещё не наступила. Начальная дата включается, конечная не включается.

Новый заказ резервирует использование кода. Оплата закрепляет использование, отмена позволяет применить код снова. Для исследования условий доступны также `OLD10`, `FUTURE10`, `OFF10`; их параметры можно посмотреть в БД.

Сервер повторно проверяет актуальные цены, активность, остатки и скидки при оформлении. Успешное оформление очищает корзину, создаёт заказ и резервирует товары. Ошибка не создаёт частичный заказ и не изменяет остатки.

## Состояния заказа

| Статус | Значение | Допустимые действия |
|---|---|---|
| `new` | Новый, ожидает оплаты | Учебная оплата или отмена |
| `paid` | Оплачен | Просмотр, повтор покупки |
| `cancelled` | Отменён | Просмотр, повтор покупки |

Автоматического истечения резерва нет. Отмена нового заказа возвращает остаток. Повторная отмена, повторная оплата и оплата отменённого заказа возвращают `409` без дополнительных изменений. Оплаченный заказ в этой версии отменить нельзя. Физическая доставка и возвраты не моделируются.

Повтор покупки добавляет все доступные товары в текущую корзину по текущим ценам. Количества суммируются; если товара недостаточно или он недоступен, пользователь получает сообщение об этой позиции. Повтор не создаёт заказ до отдельного оформления.

## Отзывы

Отзыв разрешён после оплаты покупки этого товара. Один отзыв пользователя на товар, оценка — целое от 1 до 5, текст — 10–1 000 символов после удаления крайних пробелов. Неоплаченный заказ не даёт права на отзыв. Повторная публикация возвращает `409`.

## API и интерфейс

OpenAPI и Swagger доступны по `/api/schema/` и `/api/docs/`. Базовый путь методов: `/api/v1/`. Списки возвращаются в формате `{count, next, previous, results}`, денежные значения — десятичные строки. События API хранят время в UTC, интерфейс показывает московское время с пометкой МСК.

| Код HTTP | Значение |
|---|---|
| 200 | Чтение, изменение, действие или повтор уже завершённого оформления |
| 201 | Создание |
| 204 | Удаление/выход, без тела ответа |
| 400 | Ошибка входных данных, включая неверные учётные данные |
| 403 | Нет сессии, ошибка CSRF или недостаточно бизнес-прав |
| 404 | Отсутствующий или чужой ресурс |
| 409 | Конфликт состояния, количества или повторной операции |

Ошибка имеет поля `code`, `message`, `field_errors`, `request_id`. С SessionAuthentication отсутствие входа обозначается `403 AUTH_REQUIRED`, ошибка CSRF — `403 CSRF_FAILED`. Доступ к чужому объекту определяется на сервере, а не только наличием кнопки в интерфейсе.

Для оформления требуется `Idempotency-Key` длиной до 128 печатных ASCII-символов. Повтор запроса с тем же ключом и тем же телом возвращает исходный заказ с `200`. Изменённое тело с прежним ключом — `409`. Для новой покупки нужен новый ключ. Поля `items`, `unit_price` и итоговые суммы недоступны для записи при оформлении.

Сохранение в интерфейсе должно подтверждаться сервером. Суммы, выбранный адрес, статусы и наличие соответствуют данным API. Формы поддерживают отправку Enter. На ширине 375 px основные действия доступны без горизонтальной прокрутки всей страницы.

Вне объёма: реальные платежи, почта/SMS, загрузка изображений, восстановление пароля через почту, несколько складов, возвраты и интеграции доставки.
