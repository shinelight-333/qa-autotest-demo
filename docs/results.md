# Результаты и границы проверки

## Исторические API-запуски

В исходном локальном проекте сохранились четыре pytest-html отчёта от **7 октября 2026 года**.
Для портфолио из них извлечены названия случаев, результаты, время генерации и SHA-256
исходных файлов. Выдержка: [evidence/api-runs.json](evidence/api-runs.json).
Это подготовленный структурированный артефакт, а не новый машинный отчёт о запуске.
Исходные HTML с локальными метаданными в публичный репозиторий не перенесены.

| Исходный файл | Время в отчёте | Объём | Результат |
|---|---|---|---|
| `api.html` | 19:35:58 | Все 17 API-случаев | 15 Failed, 2 Error при подготовке аккаунтов |
| `api-09-15.html` | 19:41:17 | Отдельно API-09 и API-15 | 2 Failed |
| `fixed-api-09-15.html` | 19:46:42 | Отдельно API-09 и API-15 | 2 Passed |
| `fixed-api.html` | 19:47:05 | Все 17 API-случаев | 16 Passed, 1 Failed на предусловии API-14 |

Часовой пояс старых отчётов не указан. Названия файлов с `fixed` — исходные названия,
они сами по себе не устанавливают состояние флагов дефектов и версию приложения.
Результаты повторных запусков пересекаются: их нельзя складывать как уникальные тесты.

## Что подтверждают эти файлы

- В исторических запусках действительно получены расхождения с требованиями через API.
- В первом полном запуске API-09 и API-15 не дошли до основной проверки из-за ошибок регистрации
  тестовых пользователей. Их отдельный последующий запуск уже завершился Failed в целевой проверке.
- API-01 вернул `200` вместо `404`, поиск API-07 дал 0 вместо 6 товаров,
  API-14 не вернул остаток после отмены. Эти наблюдения оформлены в [баг-репорты](bug-reports.md).
- Последний полный API-отчёт содержит 16 успешных результатов.
- Последний API-14 не дошёл до повторной проверки отмены: исходный остаток был 0 вместо 1.

Исторические отчёты не связаны с сохранённым commit приложения и тестов.
Поэтому они показывают ход учебной работы, но не подтверждают текущую работоспособность
перенесённой версии. Сохранённые хеши связывают выдержку только с исходными HTML-файлами.

## Что выполнено при выделении репозитория

Перенесены существующие Python-тесты, фикстуры, Page Objects, API-клиент и lock-файл.
Добавлены README, требования, карта покрытия, подробные кейсы, карточки дефектов и эта сводка.
Имя проекта в метаданных изменено на `qa-autotest-demo`; зависимости и проверки тестов сохранены.

Разрешённая проверка подготовки — статический разбор синтаксиса Python и TOML,
подсчёт параметризованных случаев без импорта тестов, проверка ссылок документации
и совпадения скопированных Python-файлов с источниками. Результат этой проверки
сообщается отдельно при передаче проекта; она не заменяет выполнение тестов.

## Что пока не подтверждено

- Повторный запуск API в выделенном репозитории.
- Запуск 16 UI-сценариев и smoke: исторических UI-отчётов в исходных материалах нет.
- Успешный полный прогон всех 34 случаев на подготовленном чистом стенде.
- Работа на других ОС, версиях браузеров или физических мобильных устройствах.
- Запуск в CI: workflow в репозитории отсутствует.

## Как зафиксировать следующий результат

При отдельно согласованном запуске сохраните дату с часовым поясом, версии Python/браузера/драйвера,
версию приложения и тестов, состояние учебных дефектов, состояние исходных данных,
точную команду и HTML-отчёт. Отдельно укажите Passed / Failed / Error и этап каждого падения.
Для повторения API-14 сначала подготовьте `CAMP-LAST` с остатком 1.
Новый прогон не выполняется автоматически при копировании или чтении этого репозитория.
