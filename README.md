# qa-autotest-demo

### Автоматизация тестирования демо-магазина: API + Selenium UI

![Python 3.12](https://img.shields.io/badge/Python-3.12-3776AB?logo=python&logoColor=white)
![pytest](https://img.shields.io/badge/tests-pytest-0A9EDC)
![Selenium](https://img.shields.io/badge/UI-Selenium-43B02A?logo=selenium&logoColor=white)
![Requests](https://img.shields.io/badge/API-Requests-20232A)
![Учебный проект](https://img.shields.io/badge/проект-учебный-7957D5)

Учебный QA-проект для портфолио: **34 автоматизированных сценария** для интернет-магазина
туристического снаряжения. Проверки охватывают каталог, личный кабинет, корзину,
оформление и отмену заказов, промокоды и разграничение доступа между покупателями.

Объект тестирования — демо-сайт «Поход», который разворачивался только локально.
В этом репозитории находятся автотесты и тестовая документация. Сам сайт сюда не входит.
Для выполнения тестов нужен отдельно подготовленный локальный стенд; одного клонирования
этого репозитория для полного запуска недостаточно.

**[Покрытие](docs/coverage.md) · [Тест-кейсы](docs/test-cases.md) · [Баг-репорты](docs/bug-reports.md) · [Результаты](docs/results.md)**

## Что показывает проект

- Проверки API через Requests: HTTP-коды, данные ответа и отсутствие нежелательных изменений.
- Проверки UI через Selenium с Page Object Model и явными ожиданиями.
- Подготовку пользователей и данных через API, чтобы UI-тест проверял целевой сценарий.
- Сопоставление отображения в браузере с сохранёнными серверными данными.
- Позитивный сквозной сценарий покупки и негативные проверки бизнес-правил.
- HTML-отчётность и скриншоты при падении UI-тестов.

## Быстрый старт

Понадобятся **Python 3.12**, [uv](https://docs.astral.sh/uv/getting-started/installation/)
и работающий локальный демо-стенд. Для браузерных тестов дополнительно нужны Chrome или Edge
и соответствующий ему локальный WebDriver.

Из корня клонированного репозитория:

```powershell
uv sync --locked
```

Зависимости зафиксированы в `uv.lock`. Затем в **том же окне PowerShell** настройте адрес:

```powershell
# Укажите реальный порт своего локального стенда:
$env:HIKE_BASE_URL = 'http://127.0.0.1:18080'
```

Запуск API без браузера:

```powershell
# Один сценарий, не требующий ID архивного товара:
uv run --locked pytest -m api -k api_07 --html=reports/api-07.html

# Все API-сценарии — после подготовки данных и HIKE_HIDDEN_PRODUCT_ID:
uv run --locked pytest -m api --html=reports/api.html
```

Для UI укажите путь к **уже установленному** драйверу:

```powershell
$env:HIKE_BROWSER = 'chrome'
$env:HIKE_DRIVER_PATH = 'C:\Tools\chromedriver.exe'

# Контрольная покупка:
uv run --locked pytest -m smoke --html=reports/smoke.html

# Все UI, включая smoke:
uv run --locked pytest -m ui --html=reports/ui.html

# Полный набор:
uv run --locked pytest --html=reports/all.html
```

Smoke входит в `-m ui`: складывать количество результатов этих двух запусков нельзя.
По умолчанию браузер работает в headless-режиме. Для видимого окна:

```powershell
$env:HIKE_HEADED = '1'
```

Все переменные, требования к данным и решение типичных проблем — в [подготовке окружения](docs/setup.md).
Для Linux/macOS вместо `$env:ИМЯ = 'значение'` используйте `export ИМЯ='значение'`.

## Отчётность

`pytest-html` создаёт самостоятельный HTML-файл. При падении UI в него прикладываются
скриншот и текущий URL; отдельные PNG сохраняются в `reports/screenshots/`.
Отчёт можно открыть обычным браузером:

```powershell
Invoke-Item reports\smoke.html
```

Новый запуск перезаписывает отчёт с тем же именем. Для сравнения прогонов задавайте разные
имена HTML. Генерируемые отчёты, скриншоты и локальное окружение исключены из Git.
CI в этом репозитории пока не настроен.

## Устройство проекта

```text
qa-autotest-demo/
├── tests/
│   ├── api/test_api_defects.py    # 17 API-случаев
│   └── ui/
│       ├── test_ui_defects.py     # 16 UI-случаев
│       └── test_purchase_smoke.py # Покупка и учебная оплата
├── support/
│   ├── api.py                    # HTTP-сессия, CSRF, подготовка данных
│   ├── pages.py                  # Page Objects и явные ожидания
│   └── settings.py               # Конфигурация из переменных окружения
├── conftest.py                   # Фикстуры, WebDriver, очистка, HTML-вложения
├── docs/                        # Требования, покрытие, кейсы и результаты
├── pyproject.toml               # Зависимости и настройки pytest
└── uv.lock                      # Зафиксированные версии зависимостей
```

Тесты создают пользователей с уникальными email. После сценария очищаются их корзины
и отменяются оставшиеся новые заказы. Полного удаления данных нет: публичное API
не позволяет удалить всё созданное, а оплаченные заказы расходуют общий остаток.
Запуски выполняются последовательно на отдельно выделенном учебном стенде.
